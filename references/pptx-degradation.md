# PPTX 降级 · Degradation

## 什么时候才降级

**只有用户明确要求 `.pptx` 时**才使用降级路径。其余情况一律输出 Web 演示。

原因不是偷懒，是技术边界：

| 能力 | Web | PPTX |
|---|---|---|
| 主时间轴编排（多元素先后、停顿、呼吸） | ✅ 一条 GSAP 轴 | ❌ 只有按页切换 |
| 镜头推拉 / 视差 / 景深 | ✅ transform / perspective | ❌ 仅有限缩放与动画 |
| 动态拆解（部件飞入、组装、飞散） | ✅ | ❌ |
| 逐字显现 / 逐词浮现 | ✅ | ❌ |
| 跨页形变过渡（FLIP / morph） | ✅ | ❌（PowerPoint 的 Morph 只能作用于形状，条件苛刻） |
| SVG 路径描边动画 | ✅ | ❌ |
| 数字滚动 / 图表生长 | ✅ | ❌（PowerPoint 图表动画粒度很粗） |
| 离线单文件放映 | ✅ | ✅ |
| 二次编辑的普遍性 | ❌ | ✅ |

**降级时必须明确告知用户动效受限**，不要让用户以为拿到了同等效果的东西。

## 用法

```bash
# 1. 安装依赖（国内镜像）
npm config set registry https://registry.npmmirror.com
npm i pptxgenjs

# 2. 降级导出
node scripts/degrade_to_pptx.js deck.json -o degraded.pptx
```

脚本会：

* 读取 `deck.json`，按页面顺序还原 16:9 版式；
* 沿用对应色板的背景色 / 正文色 / 强调色；
* 从 HTML 中按语义提取标题、要点、指标数字（也可在 JSON 里写 `pptx: { title, bullets }` 精确指定）；
* **在每页备注（notes）里写明**：原色板、原镜头参数、原动效类型，以及手工补动画的建议。

## 手工补动画建议（写进备注）

| 原动效 | PPT 里怎么做 |
|---|---|
| `rise` 入场 | 动画 → 淡入 + 上浮（0.4s，延迟 0.1s） |
| 逐字显现 | 动画 → 擦除 → 自左侧（0.02s 之后开始），或用 "文字分段" |
| 数字滚动 | 动画 → 强调 → 缩放；或用 `Morph` 做两个数字形状的过渡 |
| 拆解组装 | 每个部件分别加 "擦除 / 浮入"，按 0.15s 依次延迟 |
| 镜头推近 | 页面切换用 "缩放" 效果（0.8s），配合页面本身内容少 |
| 图表生长 | 动画 → 按系列 → 擦除（自底向上） |

## 更好的折中方案

如果用户的真实诉求是"要能改、能发给同事"，而不是"必须是 .pptx 文件"：

1. 用本 Skill 生成 Web 演示（动效完整）；
2. 同时用 `scripts/export_video.py` 导出 MP4 附在邮件里；
3. 需要可编辑文档时，把每页截成 PNG 放进 PPTX 作为底图，再用 PPTX 补简单动画。

这样既保住了动效，又保住了可编辑性。
